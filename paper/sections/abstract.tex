\begin{abstract}
Web application firewalls (WAFs) are widely deployed to detect and block malicious inputs, yet mutation-based payload obfuscation can still evade signature-based rules. A key contributor is the existence of parsing discrepancies: the same HTTP request may be interpreted differently by the WAF and the backend application due to differences in HTTP message processing, Content-Type handling, or ambiguous encodings. This work proposes a preprocessing-based defense that enforces deterministic, RFC-compliant HTTP normalization before inspection. We design an HTTP-Normalizer proxy that removes optional ambiguities, canonicalizes message components according to their corresponding standards, and rejects malformed requests to ensure consistent downstream interpretation. 

We evaluate the effectiveness of the approach in a pipeline of Fuzzer $\rightarrow$ WAF $\rightarrow$ Application. Thousands of mutation-based SQL injection payloads are generated and tested across multiple Content-Types, including `multipart/form-data`, `application/json`, and `application/xml`. The benchmark compares the WAF bypass rate without normalization against the bypass rate after normalization, and we further categorize remaining bypasses by the underlying discrepancy mechanism. The results indicate that RFC-based normalization substantially reduces bypass success while limiting residual gaps to non-conformant client behaviors. Finally, we analyze the security-performance trade-off of strict normalization and discuss deployment considerations.
\end{abstract}
